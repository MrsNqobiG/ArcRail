PROBES
- Probe G (would the rubric pass a bad version?) → YES. No item requires a reference artefact introduced for a detection (xpub, honeytoken list, canary mappings, WORM anchor, Treasury's list) to be modelled itself, for confidentiality as well as integrity. MC-40(b) only requires that the checked component can't write it. A TM that hands the monitor an xpub with no controls passes every MC item; only JL-6 catches it, by judgment. Proposed: "MC-40(g): every reference input has an owner, and its integrity **and confidentiality** controls are stated; if its compromise amplifies another threat (for example xpub + child key), that is a threat row".
- Probe F (would the rubric fail a good version?) → YES. The MC-40 label clause and MC-45 fail a correct, newer TM whose only fault is that it omits an "ahead" sentence, even when LEDGER already routes the sibling fix as a CF item (CF-17). Proposed rewording: "… unless the newer document says it is ahead, **or LEDGER routes the sibling fix as an open CF item naming each disagreement**".
