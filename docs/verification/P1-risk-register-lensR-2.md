CANDIDATES (Lens A):
A1 · RISK_REGISTER.md:24 RB-1 "each bank wallet does a periodic no-gas `eth_call` of a 1-wei value transfer to another bank wallet. A revert means blocklisted (C-53)" · CLAUDE.md rule 5 (never guess an Arc fact), R10 · REAL · Re-derived live on Arc testnet (https://rpc.testnet.arc.io, chain 0x4cef52 = 5042002, head ~65,179,541, read-only, 2026-10-02):
  - `eth_call {from: C-55 0x7099…79C8, to: 0xc2a6…f653, value: 0x1}` returned `{"code":-32603,"message":"Blocked address"}`.
  - The reverse direction returned the same error.
  - `eth_estimateGas` returned the same error.
  - The control (non-blocklisted sender → 0x…dEaD) returned `"0x"`, and a zero-balance sender also returned `"0x"`.
  So the probe premise holds, but the signal is not a revert. It is a JSON-RPC internal error (-32603), the generic code for many node faults. C-53 describes reverts of *included* transactions; the docs say nothing about eth_call. An implementation that follows the register literally ("revert means blocklisted") classifies -32603 as an RPC fault, so the blocklisting goes undetected (a silent miss). There is no constants row and no OPEN_QUESTIONS entry for the probe's response shape.
